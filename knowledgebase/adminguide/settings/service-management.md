# Service Management

These settings determine how Maica manages Appointments or Shifts and their function throughout the application. Please refer to the below table for more information on each setting:&#x20;

{% hint style="info" %}
The Service Management settings sections is divided into Appointment and Shift sections and the below tables describe both the individual as well as commonly shared settings.
{% endhint %}

### Individualised Settings (for Appointments and Shifts)

<table><thead><tr><th width="222">Setting</th><th width="341">Description</th><th>Applicability</th></tr></thead><tbody><tr><td><code>Default Status</code></td><td>This sets the status of the Appointment or Shift when it is first created.</td><td>Appointment and Shift</td></tr><tr><td><code>Default Schedule Status</code></td><td>This sets the status of the Appointment or Shift Schedule when it is first created.</td><td>Appointment and Shift</td></tr><tr><td><code>Default Type</code></td><td>This sets the type of the Appointment or Shift when it is first created.</td><td>Appointment and Shift</td></tr><tr><td><code>Default Duration (minutes)</code></td><td>This sets the duration of the Appointment or Shift when it is first created in minutes, for example 60 minutes.</td><td>Appointment and Shift</td></tr><tr><td><code>Default Resource Status</code></td><td>When allocating Resources to an Appointment or Shift, it is possible to set the status of this allocation to a default value, for example <code>Approved</code>. <br><br>This setting determines what this status will be when the Appointment or Shift is first created.</td><td>Appointment and Shift</td></tr><tr><td><code>Cancellation Claim Type</code></td><td>When Appointments are cancelled, Maica sets the associated Delivery Activities to a cancelled status instead of deleting them. <br><br>This is done via a <code>Claim Type</code> for any NDIS-funded Service Agreements. This setting determines which <code>Claim Type</code> Maica will use when cancelling Delivery Activities.</td><td>Appointment</td></tr><tr><td><code>Default Sections</code></td><td>An Appointment or Shift can render mutliple section, for example <code>Location</code> or <code>Schedule</code>. This is typically determined by the selected Appointment or Shift Service when selected. <br><br>This setting defines what sections are set by default, in the absence on a selected Appointment or Shift Service.</td><td>Appointment and Shift</td></tr><tr><td><code>Custom Fields</code></td><td>Maica allows you to configure a number of custom fields (Salesforce fields you have configured outside of the core Maica package) and include these into the Appointment or Shift management experience. <br><br>This setting defines what fields, including your own custom fields, will be shown when the Appointment or Shift is created/managed.</td><td>Appointment and Shift</td></tr><tr><td><code>Show Appointment Cost</code></td><td>Maica calculates the cost of an Appointment to the Participant based on the identified Service Agreement to indicate if the required funding is available.<br><br>This setting determines, in conjunction with a permission set, if the cost of Appointment will be shown when an Appointment is either created or managed.</td><td>Appointment</td></tr><tr><td><code>Enable Files</code></td><td>This setting determines if Appointment or Shift files, such as photos, are available to be attached during the management of either Appointments or Shifts.</td><td>Appointment and Shift</td></tr><tr><td><code>Enforce Agreement Leave</code></td><td><p>This setting determines whether Leave records on the Service Agreement should be enforced during Appointment configuration. If any of the recurring dates fall within a leave period defined on the Service Agreement, a warning will be shown for those dates.</p><p><br><strong>Example:</strong> A Service Agreement includes a leave from 10th–12th April. ### Other Settings (applicable to both Appointments and Shifts)

<table><thead><tr><th width="222">Setting</th><th width="549">Description</th></tr></thead><tbody><tr><td><code>Agreement Expiry Tolerance (days)</code></td><td>Maica validates Appointments against a Participant's Service Agreement to ensure that sufficient funding is available to deliver the proposed services. This validation includes checking if any given Service Agreement is expired.<br><br>This setting allows Maica to still consider an expired Service Agreement within a certain number of day following the expiry date, for example: if set to <code>30</code> then Maica will consider a Service Agreement to be active for up to 30 days after the expiry date.</td></tr><tr><td><code>Recurring Schedule Calculation Range</code></td><td>This setting controls how many recurrence entries (rows) are displayed in the Cost Breakdown section under the Recurrence tab when creating or managing an Appointment. It does not affect the number of appointments that will be created — just what’s shown on screen at once.</td></tr><tr><td><code>Appointment Service Filters</code></td><td>This setting determines how services are filtered when using the Service lookup in New/Manage Appointment modals. It restricts the options shown based on funding, ensuring only relevant Appointment Services appear according to the selected Service Agreement.</td></tr><tr><td><code>Show Accommodation</code></td><td>When managing Locations for an Appointment, this setting determines if any related Accomodation records are shown for selection. This is usually applicable to residential care scenarios.</td></tr><tr><td><code>Show Summary on Quick Complete</code></td><td>When quick-completing an Appointment or Shift, Maica can optionally show a summary screen which allows to the user to correct any delivery durations or quantities. <br><br>This setting determines if this summary screen is shown when quick-completing.</td></tr><tr><td><code>Participants Rollup Flow</code></td><td>Maica offers a Salesforce Flow that enumerates all Participants on an Appointment which can then be included into the cell description. <br><br>This setting specifies this Flow which can be changed or amdended as needed.</td></tr><tr><td><code>Resources Rollup Flow</code></td><td>Maica offers a Salesforce Flow that enumerates all Resources on an Appointment or Shift which can then be included into the cell description. <br><br>This setting specifies this Flow which can be changed or amdended as needed.</td></tr><tr><td><code>Check-Out Behaviour</code></td><td>When checking out of an Appointment or a Shift, all delivered Appointment/Shift Services can either be marked as <code>Completed</code> or <code>Not Completed</code> by default. If marked as <code>Not Completed</code>, the user is required to manually set each Appointment/Shift Service to <code>Completed</code> during the checkout process.<br><br>This setting determines which status all delivered Appointment/Shift Services will have when checking out.</td></tr><tr><td><code>Enable Appointment Tolerance Violation Policy</code></td><td>Maica has the ability to validate if Appointments or Shifts are delivered as they are meant to. This means the care worker checks in on time, runs the Appointment/Shift to the required duration and checks out at the right time. <br><br>This setting determines if Maica validates Appointments or Shifts using this logic.</td></tr><tr><td><code>Duration Tolerance (Minutes)</code></td><td>This determines how many minutes the Appointment or Shift can be varied by before it is considered violated, for example: if set to <code>30</code> then any Appointment or Shift that has a duration of more than 30 minutes over the scheduled duration will be considered violated and placed <code>Under Review</code>.</td></tr><tr><td><code>Scheduled vs Actual Tolerance (Minutes)</code></td><td>This determines how many minutes the Appointment or Shift can be varied during either check-in or check-out by before it is considered violated, for example: if set to <code>30</code> then any Appointment or Shift that has is checked into or checked out of  more than 30 minutes over the scheduled time will be considered violated and placed <code>Under Review</code>.</td></tr></tbody></table>
